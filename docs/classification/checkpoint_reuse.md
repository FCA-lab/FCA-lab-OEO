# BABD 重启检查点复用修复（2026-10-18）

## 原因

`n_jobs` 已经从任务身份中剔除；但 `rc_oeo_share` 和 `scheduler` 没有剔除。
修改配额、调度器、索引存储还改变了整个源码指纹，因此生成新 ID。
恢复逻辑过去只查新 ID 对应文件，不能发现内容兼容的旧 ID 检查点。

## 修复

- 原始源码指纹、运行参数、旧结果与耗时保留供审计。
- BABD 计算身份排除调度参数；配置源码仅排除 EXECUTION 赋值。
- 分类 runner 仅排除调度入口；worker、评分和汇总代码仍参与身份。
- 通用 runner 保留 worker 执行包装；分配顺序不参与计算身份。
- 检查点、指纹采集、索引存储模块属于运行管理，不参与 BABD 计算身份。
- 数据、样本划分、分箱、模型、投票参数、计算源码和包版本变化仍阻止复用。
- 旧版本仅通过已核验的精确源码哈希映射恢复；未知计算版本不会自动认定相同。
- 开启 resume 时，启动阶段逐文件扫描旧检查点，按计算身份匹配成功结果。
  恢复到新文件名时保留原 task 和 result，并记录 reused_from；旧文件不删除。
  失败、损坏和不兼容结果不复用。首次扫描可能需要时间，会输出进度。

## 对运行中实验的影响

未停止、重启、改写当前索引或批量迁移生产检查点。
当前父进程已经加载的恢复与调度逻辑不会热更新；下一次启动使用新逻辑。
当前运行产生的成功检查点也可在下一次启动匹配。
复用的耗时仍属于原来的并发环境，不能解释为本次调度下重新测得的耗时。
